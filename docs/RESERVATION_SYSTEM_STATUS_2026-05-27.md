# 予約管理システム 状態メモ

作成日時: 2026-05-27 19:58 JST

## 現在の判断

DOJO JAPANの予約管理システムは、現時点で小規模運用の本番環境として利用を開始できる構造になっている。

推奨する開始方法は、いきなり全会員へ一斉案内するのではなく、まずスタッフ側で実予約を数日から1週間ほど運用し、その後に数名の会員へ限定案内して確認する流れ。

## 公開URL

- 管理者予約画面: `https://dojo-japan.jp/dj-ops-6271-kuroobi/`
- 会員予約画面: `https://dojo-japan.jp/dj-member-rsv-8f3k2q/`
- LINEリッチメニュー管理画面: `https://dojo-japan.jp/dj-line-menu-admin/`

## 主な実装済み機能

- 管理者ログインはID/PASS方式。
- 管理画面は未ログイン状態では内容を表示しない。
- 会員は会員コードとPINでログイン。
- LINEブラウザではログイン状態を維持しやすいように、セッションCookieとローカル保存を併用。
- 会員画面のログアウトボタンは非表示。
- 会員側は他人の予約者名を表示しない。
- 会員側は予約数ではなく空き状況ベースで表示。
- 会員画面は「予約状況・キャンセル」と「新規予約」のタブ切り替え。
- スマートフォンでのフォーム拡大を避けるため、入力欄は16px以上。
- 管理画面は週間表示と月間カレンダー表示に対応。
- 日付をタップして、その日の枠を確認・管理できる。
- 管理者は会員登録、営業管理、会員管理、NGチェックを操作可能。
- 会員登録後に、LINE / Instagram / メール向けの案内文を発行できる。
- 会員コードはランダムな5桁数字。
- 会員の休会・削除に対応。
- 休会中、削除済み会員は予約不可。
- 会員ごとの特別追加枠はその月のみ有効。
- 退会予定日または休会予定日の管理に対応。
- NG会員同士が同じ枠に入っていないか確認可能。
- 営業管理で午前・午後・全日の予約不可設定が可能。
- 毎週日曜日は予約不可。
- 第一土曜日の午前は予約不可。
- 7:00から18:00は正会員も予約が必要。
- 18:00以降は通常予約枠としては作成しない方針。
- 担当者名を枠ごとに表示。
- 通常は午前が `SATORU成合`、午後が `松島勲也`。
- 管理者は枠ごとに担当者を一時変更可能。
- パーソナル予約に対応。
- パーソナル予約は空き6/6の枠のみ可能。
- パーソナル予約はその枠を満席扱いにする。
- パーソナル予約はチケット消費に加えて別途3000円。
- 正会員はチケット消費なしで別途3000円。
- パーソナル予約は6時間前まで。
- 当日のキャンセルは不可。
- 通常予約は1時間前まで可能。
- キャンセル制限は3時間前を基準に案内。
- 初回体験、ビジター予約は翌日以降に案内する方針。

## LINE連携方針

- 公式LINEの会員向けタブから会員予約画面へ誘導する。
- 初回は会員がLINEへ名前を送信し、スタッフ側で会員登録後に案内文を送る。
- 会員は初回のみ会員コードとPINを入力。
- 以後はLINEの予約ボタンからスムーズに開けることを目指す。
- LINEを使わない会員はSafariやChromeで会員予約URLを開き、ホーム画面追加で対応可能。
- 将来的に公式LINEを使わなくなっても、会員予約URLとID/PIN方式で継続可能。

## データ保存と構造

- 会員、予約、営業不可、担当者上書き、NG会員などはCloudflare D1に保存。
- 予約上限はDB側の集計とAPI側の判定で保護。
- 予約APIは未認証ならJSONで `401 / UNAUTHORIZED` を返す。
- APIレスポンスは `no-store` 系ヘッダーを付け、会員間キャッシュ干渉を避ける構成。
- 管理者が手入力した未登録予約は `MANUAL` として扱う。

## 前回までの重要検証

- 7人同時予約相当の検証で、6人までは予約成立、7人目は `SESSION_FULL` で拒否されることを確認。
- 満席時にHTMLエラーではなくJSONエラーを返すよう修正済み。
- パーソナル予約後、同じ枠への通常予約は満席として拒否されることを確認。
- 会員側の予約後に自分の予約状況へ反映されることを確認。
- 会員側キャンセル後に自分の予約状況から消えることを確認。
- 検証用QAデータは削除済み。

## 残る注意点

- 管理者の実ID/PASSを使った本番画面の全クリック検証は、認証情報が必要なため最終的には実端末で確認する。
- LINEブラウザのログイン保持は端末やLINEアプリの状態に左右されるため、実会員数名での確認が必要。
- CloudflareやLINEの一時障害に備え、当面は手動確認できる運用ルールを持つ。
- バックアップやGoogleスプレッドシート連携は、必要性が高まった時点で追加検討する。
- 本番開始後は、予約したはずなのに反映されない、キャンセルできない、ログインが保持されない、という3点を重点的に観察する。
